# 精靈與巨魔 — 建築系統原型（規格 V0.6）

Godot 4.4 單機權威原型。純邏輯（`core/`）與畫面（`game/`）分開，日後把 `core/` 搬到權威伺服器即可，畫面只送指令。

## 怎麼跑

1. 用 Godot 4.4（或更新的 4.x）開啟這個資料夾，按 ▶ 執行。
2. 自動測試（不開畫面）：
   ```
   godot --headless --path . --script res://tests/run_tests.gd
   ```
   目前 23 項全部通過，涵蓋規格第 7 節的 10 項必測。

## 操作（手機 / 滑鼠皆可）

- **上方**：切換操控精靈 1/2/3 或巨魔（單機測試用），速度 x1/x4/x10、暫停、縮放、「找我」。
- **點空地**：移動。**拖曳**：移動鏡頭。
- **建造**：右側選建築 → 點地圖看綠/紅預覽 → 再點同一格或按「確認放置」。城牆會停留在建造模式方便連續放。
- **點建築**：看資訊，可升級／取消（顯示退款）／續建／修繕（顯示修滿費用）／拆除。
- **巨魔模式**：點精靈或建築＝攻擊，點空地＝移動；可關閉自動 AI。
- **測試工具**：加錢、跳到 12:00、跳到 24:50、巨魔立刻出場、重新開局。

## 調數值不用改程式

| 檔案 | 內容 |
|---|---|
| `data/buildings.json` | 9 種建築的占地、上限、每級追加成本、時間、HP、產量、攻擊、緩速、前置；傳送門三階段 |
| `data/match_config.json` | 25:00、12:00 解鎖、初始資源、修繕 40 HP/秒與 70%、退款 50%、傳送門加速、精靈/巨魔/僕從/靈魂數值 |
| `data/maps/proto_map.txt` | 文字地圖：`#` 森林、`.` 空地、`P` 傳送門保護區、`g` 保護區入口、`T` 巨魔出生區、`1~3` 精靈出生點 |

`match_config.json` 中標 `_placeholder` 的（巨魔血量傷害、收益係數、僕從、靈魂能量、巨魔 90 秒出場、20 秒重生）都是規格留給下一份文件的占位值。

## 程式結構

```
core/defs      BuildingDefinition、DefinitionDB（讀 JSON 並驗證）
core/state     BuildingInstance、UnitState、PlayerAccount
core/grid      TileGrid（地形、占格、BFS）、GridMath（距離定義）
core/services  Economy / Building / Combat / Repair / Visibility / Escape / Match / Unit
core/sim       MatchSim（10 tick/秒、submit 指令、request_id 去重）、EventBus
game/          main.gd（觸控、HUD）、map_view.gd（色塊地圖）
tests/         自動測試
tools/         screenshot.gd（開發用截圖）
```

每 tick 順序：巨魔出場 → 視野 → 單位移動與攻擊 → 建築施工 → 傳送門施工 → 修繕 → 塔攻擊 → 每秒產量 → 勝負判定（規格第 5 節順序）。

## 規格沒寫清楚、目前採用的預設

1. 施工中普通建築從 10% HP 隨進度長到滿；施工中受的傷會保留到完工。
2. 普通建築的建造與升級都要擁有者在 2 格內施工，別人不能代蓋；走開或接新工作就暫停，可按「續建」。
3. 城牆擋所有單位（含精靈）；建傳送門只檢查發起者走得到門 3 格內。
4. 傳送門每階段完成後停住，由任一存活精靈按「支付下一階段」付款。
5. 多人施工：2 人 +15%、3 人以上 +30%。施工範圍＝所在格到門的 Chebyshev 距離 ≤ 3。
6. 傳送門前置的大廳 Lv2、樹屋 Lv4 都看發起者自己的。
7. 冰霜塔單體施放，選敵同箭塔。
8. 升級中取消也套 50% 公式；完工後拆除不退款。
9. 所有建築升級都保留血量比例（規格只寫城牆）。
10. 修繕成本只算已完成等級的累計費用；採「整枚預付、餘額記帳」，小額連修不會少付。
11. 修繕站對靈魂修復同樣加速；修繕站 +25% 只取一座，不疊加。
12. 巨魔死亡會在 20 秒後於出生區重生（占位）。
13. 測試用巨魔 AI 會在「最近的精靈」與「最近的可攻擊建築」之間挑路徑成本最低的，精靈成本打 6 折；牆擋路就先打牆。它不是正式 AI。
